## 3. 🏆 Выбор источника и техническое обоснование

Для реализации пилотного адаптера выбран **ЕАСУЗ Московской области (`easuz.mosreg.ru`)** по следующим причинам:

1. **Прямой структурированный JSON**: Страницы отдаются через Angular SSR с внедренным блоком TransferState (`<script type="application/json">`). Это позволяет извлекать точные данные (НМЦК, даты, заказчик, ИНН, статус) без ломкого парсинга верстки.
2. **Отсутствие блокирующей капчи**: В отличие от федерального ЕИС, витрина ЕАСУЗ стабильно отдает данные по HTTP без применения браузерной эмуляции (Selenium/Playwright).
3. **100% покрытие целевого региона**: Все закупки жестко привязаны к городам и округам Московской области.

## 4. ⚙️ Техническая реализация

### 4.1. Архитектура сервиса

```
easuz_pilot/
├── app/
│   ├── adapters/
│   │   └── easuz.py       # Адаптер ЕАСУЗ МО (SSR TransferState JSON + DOM fallback)
│   ├── ai/
│   │   └── classifier.py  # AI-классификатор (Polza.ai / GPT-5.6 Luna + rule-based prefilter)
│   ├── models.py          # Pydantic v2 модели (Tender, Classification, Profile, MatchResult)
│   ├── matching.py        # Движок скоринга под профиль подрядчика
│   ├── database.py        # SQLAlchemy 2 async (PostgreSQL / SQLite) + идемпотентный upsert
│   ├── pipeline.py        # End-to-end оркестратор: fetch → dedupe → AI → match → PostgreSQL
│   ├── cli.py             # Единый CLI (команды scan, report, view)
│   └── bot.py             # Telegram-бот на aiogram 3 для просмотра карточек и разметки
├── docs/
│   └── sources_research.md # Расширенный аналитический отчет по 7 площадкам
├── tests/                 # 8 автоматических тестов (100% offline на фикстурах)
├── docker-compose.yml     # PostgreSQL 16 Alpine
├── report_metrics.json    # Дамп 100 реальных закупок с AI-разбором
└── requirements.txt       # Зависимости проекта
```

---

### 4.2. Адаптер источника (`app/adapters/easuz.py`)
- Считывает каталог процедур с пагинацией и детализацию каждого лота.
- Автоматически парсит как TransferState JSON, так и HTML DOM в случае нестандартной разметки.
- Содержит семафоры параллелизма (`max_concurrency=3`) и настраиваемые задержки.

---

### 4.3. Нормализация данных и дедупликация (`app/models.py`)
- Каждая закупка валидируется схемой `Tender` в Pydantic v2 (типизация `Decimal`, `datetime`, `HttpUrl`).
- **SHA-256 Fingerprinting**: Формируется детерминированный хэш от `нормализованное_название | заказчик | бюджет`. Это исключает дублирование при повторном сборе или объединении источников.

---

### 4.4. LLM-классификация со структурированным JSON (`app/ai/classifier.py`)
AI-модель (**GPT-5.6 Luna** через шлюз Polza.ai) анализирует закупку и возвращает строгий JSON по схеме `TenderClassification`:

```json
{
  "is_relevant": true,
  "category": "demolition",
  "work_types": [
    "снос аварийных многоквартирных жилых домов",
    "вывоз и утилизация строительного мусора"
  ],
  "region": "Московская область",
  "city": "Сергиев Посад",
  "address": "г. Сергиев Посад, ул. Центральная",
  "object_type": "residential",
  "budget_min": 8405781.72,
  "budget_max": 8405781.72,
  "area_sqm": null,
  "volume_cbm": null,
  "requirements": ["СРО на снос", "лицензия на обращение с отходами"],
  "confidence": 0.95,
  "reason": "Закупка предусматривает снос расселенного аварийного жилого фонда с утилизацией отходов."
}
```

---

### 4.5. База данных PostgreSQL (`app/database.py` + `docker-compose.yml`)
- Хранение организовано в **PostgreSQL 16** с асинхронным драйвером `asyncpg`.
- Реализован идемпотентный `upsert_tender`: при повторном сборе данные обновляются без дублирования строк.
- Поддерживается быстрое переключение на `SQLite` для локальных тестов.

---

### 4.6. Telegram-бот (`app/bot.py`)
Запущен и доступен по адресу **[@easuztest_bot](https://t.me/easuztest_bot)**:
- **Интерактивные карточки**: Название, бюджет, заказчик, срок подачи заявок, вердикт AI, типы работ.
- **Кнопка-ссылка**: `🔗 Открыть карточку на ЕАСУЗ` — переход на официальную страницу торгов.
- **Кнопки разметки**: `👍 Подходит` / `👎 Не подходит` — сохранение статуса в PostgreSQL и переход к следующему лоту.
- **Вкладки**: `📋 Все закупки`, `⭐ Подходящие`, `📊 Статистика`, `⚙️ Профиль поиска`.

## 5. 🚀 Инструкция по запуску

### 1. Клонирование и установка

```bash
git clone https://github.com/gajsin/pilot.git
cd pilot

python3 -m venv venv
source venv/bin/activate  # На Windows: .\venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Запуск PostgreSQL через Docker

```bash
docker compose up -d
```

### 3. Настройка окружения (`.env`)

```bash
cp .env.example .env
```
Заполните параметры в `.env`:
```env
TELEGRAM_BOT_TOKEN=ваш_токен_бота
DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/opportunity_pilot
OPENAI_API_KEY=ваш_ключ_polza_или_openai
OPENAI_BASE_URL=https://polza.ai/api/v1
OPENAI_MODEL=openai/gpt-5.6-luna
```

### 4. Запуск автоматических тестов

```bash
python -m pytest -v
```
*(Все 8 тестов проходят 100% автономно на встроенных фикстурах).*

### 5. Сбор 100 закупок и генерация отчета

```bash
python -m app.cli report --category 13987 --limit 100
```

### 6. Просмотр данных в терминале

```bash
python -m app.cli view
```

### 7. Запуск Telegram-бота

```bash
python -m app.bot
```
